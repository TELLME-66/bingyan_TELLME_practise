# 版本更新与补丁修复流程

写给「归位」这个项目后续的维护。假设读者不熟悉 git，所有命令都可以直接复制。

---

## 一、先理解三件事

### 1. 版本号长什么样

`1.2.3` 这样的三段式，叫**语义化版本**：

```
  1  .  2  .  3
  │     │     └── 修订号：修了 bug，没有新功能
  │     └──────── 次版本号：加了新功能，但老功能不受影响
  └────────────── 主版本号：大改版，界面或用法可能完全变了
```

举例：

| 你做了什么 | 版本从 | 变成 |
| --- | --- | --- |
| 修了「灵动岛点了没反应」 | 1.0.0 | **1.0.1** |
| 加了「批量导入物品」 | 1.0.1 | **1.1.0** |
| 换了全新的界面风格 | 1.1.0 | **2.0.0** |

### 2. 版本号写在哪儿

在 `GuiWei/GuiWei.xcodeproj/project.pbxproj` 里，有两个字段：

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| `MARKETING_VERSION` | **用户看到的版本号** | `1.0` |
| `CURRENT_PROJECT_VERSION` | **构建号**，每上传一次 App Store 就要加一 | `1`、`2`、`3` |

> 它们在 App 和小组件扩展两个 target 里各出现两次，**一共 4 组**。
> 必须全部一致，否则两边版本不匹配。脚本会自动改全部，不用手动找。

### 3. 提交信息为什么重要

半年后你回头看「这个版本改了什么」，全靠这些信息。本项目用**约定式提交**：

| 前缀 | 什么时候用 | 例子 |
| --- | --- | --- |
| `feat` | 新功能 | `feat(siri): 支持一句话找东西` |
| `fix` | 修 bug | `fix(灵动岛): 修复点击收起无效` |
| `docs` | 只改了文档 | `docs: 补充发版流程` |
| `chore` | 杂活（配置、依赖、gitignore） | `chore: 忽略安卓目录` |
| `refactor` | 重构，行为不变 | `refactor: 抽出物品查询逻辑` |
| `style` | 只改格式，不影响功能 | `style: 统一缩进` |

括号里是**影响的范围**，可省略。

## 二、三种日常场景

### 场景 A：改了点东西，想保存并备份

```bash
cd ~/Desktop/bingyan

./发版.sh status              # 先看看改了哪些文件
./发版.sh build               # 编译，确认没写错
./发版.sh save "fix: 修复列表页滑动删除后不刷新"
```

`save` 会自动：暂存 → 提交 → 推送到 GitHub。

> **建议**：每完成一件小事就 `save` 一次，不要攒一大堆。
> 这样出问题时能精确回到某个点。

### 场景 B：修了一个 bug（打补丁）

补丁的本质就是「改代码 + 提交」，只是版本号要加一位：

```bash
# 1. 改代码、编译、在模拟器上验
./发版.sh build
./发版.sh run                 # 装到模拟器看效果

# 2. 版本号第三位 +1（1.0 → 1.0.1），构建号 +1
./发版.sh ver 1.0.1 2

# 3. 提交并打补丁标签
./发版.sh save "fix(灵动岛): 修复点击收起按钮无效

DismissIslandIntent 只定义在扩展 target，App 的 App Intents
元数据里没有登记，而 LiveActivityIntent 由系统在 App 进程执行，
所以按钮点了没反应。已在 App target 补上定义。"
```

> 提交信息可以写多行：第一行是摘要，空一行再写详细原因。
> **详细原因很值钱**——它记录的是「当时为什么这么改」。

### 场景 C：正式发一个版本

```bash
./发版.sh release 1.1.0 "feat: 支持批量导入物品"
```

它会依次：改版本号 → 编译（不过就不发）→ 提交推送 → 打上 `v1.1.0` 标签 → 推送标签。

标签的作用是**在历史上钉一个书签**，以后随时能回到这个版本：

```bash
./发版.sh tags                # 看所有版本
git checkout v1.1.0           # 回到 1.1.0 去查问题
git checkout main             # 查完回到主线
```

## 三、出问题了怎么办

### 情况 1：刚提交，发现漏了个文件

```bash
# 直接补上，再提交一次
./发版.sh save "chore: 补上遗漏的文件"
```

### 情况 2：刚提交，发现改错了，想重来

```bash
./发版.sh undo                # 撤销提交，但代码改动保留
# 改好之后重新提交
./发版.sh save "fix: 修正上次提交的错误"
```

> `undo` 用的是 `git reset --soft`，**只撤销「提交」这个动作，文件内容原样保留**，不会丢代码。
> 如果已经推送过，撤销后需要用 `git push --force-with-lease origin main` 才能覆盖远程。

### 情况 3：线上版本有严重 bug，要回到上一个版本

```bash
git log --oneline -10          # 找到上一个正常版本的编号
git revert <那个编号>          # 生成一个「反向操作」的新提交
./发版.sh save "fix: 回滚到上一个稳定版本"
```

> 用 `revert` 而不是 `reset`：它**不删除历史**，而是新增一个抵消的提交，
> 更安全，也便于以后重新把功能加回来。

### 情况 4：编译突然过不去了

```bash
# 九成是缓存脏了，先清缓存重来
rm -rf GuiWei/.build
./发版.sh build
```

如果还不行，用 `git stash` 暂时收走改动，确认是不是自己的代码引起的：

```bash
git stash          # 收起所有未提交的改动
./发版.sh build     # 如果现在能编译，说明是刚才的改动有问题
git stash pop      # 把改动放回来
```

## 四、每次提交前的检查清单

- [ ] `./发版.sh build` 编译通过，**没有 error**
- [ ] 模拟器上真的跑过一遍（`./发版.sh run`）
- [ ] 涉及灵动岛 / 通知 / Siri 的改动，**真机上验过**
- [ ] `./发版.sh status` 里**没有**安卓版、本地资料、答辩手册
- [ ] 提交信息说清了「改了什么、为什么」

> 第 4 条已经被 `.gitignore` 挡住了，脚本里也加了二次检查，会直接中止。

## 五、这个项目特有的注意点

### 1. `GuiWeiActivityAttributes.swift` 有两份，必须同步

```
GuiWei/GuiWei/LiveActivity/GuiWeiActivityAttributes.swift          ← App 用
GuiWei/GuiWeiWidgetExtension/GuiWeiActivityAttributes.swift        ← 扩展用
```

App 和小组件扩展是两个独立 target，不能共享文件，所以各存一份。
**改了其中一份就必须同步另一份**，否则两边数据结构不一致，灵动岛会渲染失败或崩溃。

检查是否一致：

```bash
diff GuiWei/GuiWei/LiveActivity/GuiWeiActivityAttributes.swift \
     GuiWei/GuiWeiWidgetExtension/GuiWeiActivityAttributes.swift \
  && echo "✓ 一致"
```

### 2. App Intent 必须同时存在于两个 target

`DismissIslandIntent` 这类给实时活动按钮用的意图：

- **扩展 target 那份**：负责把按钮画出来
- **App target 那份**：负责真正执行（`LiveActivityIntent` 由系统在 App 进程里跑）

只写扩展那份，按钮会「看得见、点不动」。

验证方法：

```bash
cd GuiWei/.build/Build/Products/Debug-iphonesimulator
strings GuiWei.app/Metadata.appintents/extract.actionsdata | grep DismissIslandIntent
```

有输出才算登记成功。

### 3. 改实时活动后无法在模拟器上验证外观

无界面的模拟器**不合成灵动岛图层**，截图里看不到药丸。
所以灵动岛的任何视觉改动，**必须真机验证**。

### 4. 真机安装靠 Xcode

```bash
open GuiWei/GuiWei.xcodeproj
```

然后在 Xcode 里选自己的 iPhone，按 `⌘R`。免费 Apple ID 的证书**7 天过期**，
过期后重新 `⌘R` 一次即可。

## 七、推荐的日常节奏

```
改代码  →  ./发版.sh build  →  模拟器跑  →  真机跑（涉及系统功能时）
   ↑                                              │
   └────  ./发版.sh undo  ←──  发现问题  ←────────┘
                                   │
                              没问题 ↓
                        ./发版.sh save "说明"
```

**小步提交，频繁提交。** 每次提交都是一个可以退回的安全点。
